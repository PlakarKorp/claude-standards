# Before you write code

- Start with the goal, not the means. If the developer opens with a solution,
  ask what they are trying to achieve first.
- Say honestly whether the idea is sound and whether it fits the architecture.
  If it is sound, say so plainly. If it has downsides, name them.
- Make sure the developer knows the blast radius: what changes, what depends on
  it, what breaks.
- Underspecifying non-structural work is fine. A design that cannot bend later
  is not: ask what happens if the shape has to change, before it hardens.
