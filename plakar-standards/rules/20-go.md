# Go

Formatting is handled for you: gofmt runs after every write. These are the rules
a formatter cannot enforce.

## Errors

- Wrap with context and `%w`: `fmt.Errorf("open snapshot %s: %w", id, err)`.
  Lowercase, no trailing punctuation, no "failed to" prefix.
- Handle an error or return it, never both. Logging and returning gives the
  caller a decision it cannot make and the reader two reports of one failure.
- `errors.Is` / `errors.As` for comparison. Never string matching.
- Sentinel errors are `var ErrFoo = errors.New("foo")` at package scope.

## Control flow

- No `panic` outside `main` and package `init`. A backup tool that panics on
  malformed input has lost the user's data run.
- Return early. Do not nest the happy path inside an `if`.
- Every goroutine has an owner that knows when it stops. A goroutine started
  without a `context`, a `WaitGroup`, or a channel to signal completion is a
  leak, not concurrency.
- Every `context.Context` is honoured: check `ctx.Err()` in loops that can run
  long, and pass it down rather than storing it in a struct.

## Resources

- `defer` the close on the line after the open, always. Check the error from
  `Close` on anything that writes.
- No unbounded reads of attacker-controlled input. `io.LimitReader` or a
  documented cap.

## Types and APIs

- Accept interfaces, return concrete types.
- Keep interfaces at the consumer, not next to the implementation.
- Zero value should be usable where that is cheap to arrange.
- Exported identifiers have doc comments starting with the identifier name.

## Tests — Go mechanics

- Table-driven with named subtests via `t.Run`.
- `t.TempDir()` and `t.Cleanup`, never a hand-rolled temp path or a global.
- No `time.Sleep` to synchronise. Use channels, `sync`, or a fake clock.
- Tests must pass under `-race`.
